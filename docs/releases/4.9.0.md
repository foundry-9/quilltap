*4.8 rebuilt the floor plan so you could stand in several rooms at once — a conversation streaming in the left pane, a document open in the right, a terminal beside the chat that spawned it. What 4.8 could not do was tell you anything. Every surface in that wall of tabs sat there asking, every few seconds, whether anything had happened yet: the errand queue polled, the autonomous rooms polled, the backdrop watcher polled, and each clock on the screen ticked to its own private schedule so no two "4m ago"s ever turned over together.*

*4.9 is the release in which the house stops asking and starts being told.*

---

Where 4.8 gave you the rooms, 4.9 makes them attentive. The headline is **realtime**: one multiplexed socket carrying word of what has changed to every open tab, so a finished errand, a room waking up, or a freshly painted backdrop arrives the moment it happens rather than up to eight seconds later. Around that, four further bodies of work define the cycle. The **wardrobe** stops being a character's private closet and becomes the house's clothing system: one dialog browsing all four wardrobes, plain-language instructions on how each one's owner likes to dress, and outfits that bring their component garments with them when they move. **Archiving** — which 4.8 gave to characters — comes to scenarios and garments, on the principle that putting a thing away is not the same as destroying it. The **search bar** learns to read the library, matching document text across every store you have. And the **system prompt** finally addresses a character the way it has been claiming to since the first line: in the second person, throughout, with no block quietly talking about her behind her back.

Five more earned their places. A chat's **scene can now be changed mid-conversation** rather than being fixed at creation. **NanoGPT** arrives as a bundled provider carrying chat, images, and embeddings on a single key, and the image-profile editor learns to ask providers what they actually have rather than reciting a hardcoded list. Characters can **look at a photograph** — a defect that ran five bugs deep, in which four plugins stripped every image off the wire and the model wrote a confident paragraph about a picture it had never seen. Group scenes stop turning into **committee meetings** where every character answers the same question in turn. And the **Commonplace Book** can consult a character's past conversations on every turn instead of only at the folds, at no extra cost, because the vector it needs was already embedded a moment earlier.

Three arrived late and would have carried a release of their own. A connection profile can now name an **understudy** — when a provider rejects the key, throttles, times out, or hands back nothing at all, the call is tried again somewhere else rather than simply failing. Image profiles gained **LoRA adapters**, with the editor asking each model what options it genuinely supports instead of reciting a hand-written list, and a **Query** button that reads an adapter's card off HuggingFace and tells you what it says. And the **Concierge** grew a fourth state, so that "I have decided this chat is spicy" and "the classifier decided this chat is spicy" stop being the same button.

One thing leaves. The **managed Linux virtual machines** — Lima on macOS, WSL2 on Windows — are withdrawn from the desktop shell and from the server that ran inside them. Docker is the sandbox now. A virtual machine of your own making remains entirely supported; the difference is who builds it.

The thesis is simple: *4.8 let you occupy all the rooms. 4.9 makes them notice things — and tells you.*

## The House Notices

### Realtime, and the End of Polling

Every screen in Quilltap used to run on a timer. The toolbar's errand chips asked the server every second and a half whether the queue had moved; autonomous-room badges asked every few seconds; the story-background watcher kept both a passive sweep and an active loop; the tasks queue had a switch labelled "Auto-refresh (5s)," which was an honest description of a dishonest arrangement. Nothing was ever *late* by much, but nothing was ever right either, and a perfectly idle instance spent its evening asking itself questions.

A single multiplexed WebSocket now carries the answers instead. It is deliberately, almost insultingly small: a frame is about forty bytes, and it says *what changed*, never *what it changed to*. The client takes that hint, throws away the affected queries, and re-reads through the REST API — so the API stays the one source of truth, a reconnect is simply "invalidate everything and refetch," and there is no second copy of your data taking a shortcut through a socket. An older tab that meets a newer server ignores topics it has never heard of rather than breaking.

Behind it sits a parent-process fan-out bus with a mandatory quarter-second debounce, so twelve errands enqueued in the same instant arrive as one frame rather than twelve. Errands publish when they are queued, claimed, finished, failed, or cancelled; autonomous rooms publish their run-state transitions; and every write a background job makes reaches the bus through the dispatcher after it lands, which means the child process needs to know nothing about any of this.

**Polling did not go away — it was demoted.** Every migrated surface keeps its original cadence wired up and gated on whether the socket is healthy, so an instance behind a proxy that eats WebSocket upgrades behaves exactly as 4.8 did rather than going quiet. The tasks queue's switch is now labelled "Fallback polling (5s)," which is the same switch telling the truth. On a live instance, a ten-second idle window that previously cost at least one background fetch now costs none.

The upgrade path is also, at last, actually guarded. Both WebSocket handlers — the terminal's and the new one — authenticate through a single gate that requires a live session, an unlocked instance, and a same-origin request. The terminal handler previously accepted "a session-ish cookie exists," which proved nothing whatsoever, Quilltap setting no session cookie; and because browsers do not apply CORS to WebSocket upgrades, the origin check is the only thing standing between a localhost instance and any website that cares to open a socket against it.

### One Clock for the Whole House

The second cause of a stale screen was not the server at all. Every relative timestamp on screen — "4m ago," "Today," a budget counting down — ran its own interval, started whenever its component happened to mount, so they drifted apart and turned over one at a time like a badly wound orchestra. There is now one shared ticker per granularity, aligned to the boundary rather than to the mount: it fires just after each minute, each second, and each local midnight, so every "4m ago" in the house becomes "5m ago" together, and a chat card rolls from Today to Yesterday at midnight rather than whenever it feels like it. It is inert during server rendering and pauses entirely while the tab is hidden.

### A Chat Is Dated by When Somebody Spoke

The dates on the chat lists were, strictly speaking, true and entirely useless. A chat's timestamp moved whenever anything about it changed — and because story backgrounds, context summaries, and every Staff announcement the house makes are stored as messages, a conversation nobody had touched since May could rise to the top of the dashboard dated four minutes ago, with nothing said in it. The Lantern finishing a backdrop is not the conversation resuming.

Every surface that shows or sorts by a chat's date — the dashboard, the Salon list, a project's or a character's conversations, the merge picker, the Brahma Console — now shows the last time **the user or an LLM character actually posted content**. Whispers to particular participants count, being speech. Staff announcements, announcements posted under a custom name, tool results, and system events do not. Delete the most recent message and the date walks back to the one before it. A chat in which nobody has ever spoken is dated by its creation, which is the only honest answer available.

Restore learned the same lesson in passing: replaying a backup's transcripts used to stamp every chat with the moment of the restore, so a decade of conversation arrived bearing one timestamp and no order. Each chat's date is now recalculated from the transcript just written.

### Labels That Behave Like Labels

Every control beneath a Salon message used to name itself with the HTML `title` attribute, which hands the job to the operating system's own tooltip: about a second of motionless hovering, gone at the smallest twitch of the pointer, unwilling to return without leaving and re-entering, and truncated when the text ran long. The answer-confirmation badge suffered worst, since its `title` carried the discrepancy notes and the pre-revision text — a paragraph delivered through a widget that would not hold still.

Quilltap draws its own now. The bubble opens after a fifth of a second of hover, or immediately on keyboard focus; it flips above or below as the viewport requires, clamps to the screen edge, follows its anchor while the page scrolls, and closes on Escape. The eleven action-bar buttons each gained a proper accessible name to go with it — a tooltip is a courtesy, not a label, and screen readers were never being told anything. The verdict badge is now a real button that answers hover and focus like the icons beside it, holds open when clicked, and renders its contents as structure rather than a wall of `title` text: the verdict, the summary, what looked off, and what was originally written.

## The Closet Becomes a Wardrobe

### Four Wardrobes, One Dialog

Clothing in Quilltap has always lived in four tiers — a character's own vault, a group's store, a project's store, and Quilltap General — but the Wardrobe dialog only ever showed you the first. The other three could be reached solely by moving something into them and hoping. The dialog's top dropdown now lists every container a garment can live in, and selecting a shared one shows exactly its contents with the full menu behind each item: edit, star as default, duplicate, move, copy, delete, and a `+ New Item` that creates directly in that container. The group tier gained the CRUD endpoints it had somehow never had, so a group's clothes are now first-class rather than reachable only by transfer.

### Instructions for Getting Dressed

Every wardrobe may now hold an optional `Wardrobe/instructions.md` — plain second-person guidance about how that closet's owner likes to dress, read when a character dresses themselves at the start of a chat. Resolution is nearest-tier-first (character, then group, then project, then General), the first non-blank file wins, and the content influences the outfit choice and absolutely nothing else. It is edited from a collapsible panel in the Wardrobe dialog, or from the Wardrobe tab of a character's Aurora page.

The file is scrupulously not a garment: the wardrobe reader skips it by name rather than parsing it as an invalid item and complaining on every read, the projection sweep preserves it rather than deleting it on the next write, a garment actually titled "Instructions" is filed as `instructions-1.md` instead of overwriting it, and the Almanack's garment counts leave it out.

### Wearing an Outfit in One Gesture

The outfit composer — the chat-start Starting Outfit panel and both dressing columns of the Wardrobe dialog — now opens with a **Wear an outfit…** pull-down above the five slot rows, listing every composite in the character's wearable pool with the slots it claims and whether it replaces them. Picking one takes the same path a slot picker does, so an additive ensemble layers, one marked *replace* sweeps its slots first, and either way it dissolves into its component garments as it lands.

The per-slot `+` pickers, in exchange, no longer offer composites at all. A three-slot ensemble used to appear once in each slot it covered, pushing the garments actually meant for that slot down the list; it now appears exactly once, in the pull-down. A multi-slot *leaf* — a dress typed `["top","bottom"]` — is not a composite and stays where it was.

### Outfits That Travel With Their Clothes

Moving a composite outfit between containers used to move the outfit and leave its component garments behind, pointing at items that were often unresolvable at the destination — a preset for clothes that were no longer there. The transfer dialog now asks: move the components too, copy them and leave the originals, or leave them entirely; copying offers to copy them or not. The choice is all-or-nothing and follows nested composites all the way down. Only components living in the same source container travel, since shared-tier pieces are reachable from anywhere already. When copies mint new identities the outfit's references are rewritten to match, and a post-write verification reads the outfit back from the destination to confirm every reference resolves. Copying an outfit while moving its components is refused outright, since it would strand the original.

Verifying that contract turned up a latent defect worth its own paragraph. Component references are stored as title slugs, and two garments sharing a title in one container produced a slug that the writer assigned to one item and the reader resolved to the other — so an outfit could silently rewire itself between one read and the next. An ambiguous slug is now assigned to nobody, and every reference to a colliding item is written as an exact identity instead.

### A Slot for Hair

The wardrobe gained a **hair** slot, for hairdos rather than hair itself — the arrangement is a thing a character puts on and takes off; the hair is a physical description. Both the outfit resolution and the image pipelines understand the distinction.

## Putting Things Away

### Archivable Scenarios and Garments

4.8 taught the house to archive a character. 4.9 extends the same courtesy to scenarios and wardrobe items, on the same principle: a thing whose time has passed should be able to leave the lists without being destroyed.

An archived scenario or garment disappears from every list, dropdown, and picker. Each listing surface gained a **Show archived** checkbox that brings it back, badged, and still selectable — because archiving hides, it does not forbid. A garment archived in the middle of a chat stays worn. A chat whose scenario was archived after the fact keeps its scene. The one hard rule, with no parameter and no override, is that the outfit-selection LLM at the start of a chat never sees an archived garment in any tier: the point of putting a dress away is that nobody puts it back on absent-mindedly.

Scenarios carry the state as an `archived: true` frontmatter key across all four scopes, omitted entirely when the scenario is active, so a hand-written file with nothing but that line works exactly as expected. An archived scenario can never win a default-conflict or be auto-selected in the New Chat dialog, even while it is being listed. Filtering is server-side throughout — the checkboxes change what is fetched rather than filtering what arrived — so a picker that simply never asks for archived entries is safe by construction, and the two client-side filters that used to exist were removed rather than left as a second place for the rule to drift.

## The Search Bar Reads the Library

The global search bar gained a **Documents** type and its own filter chip beside Chats, Characters, Messages, Tags and Memories. It matches file names, relative paths, and extracted document text across every enabled document store — character vaults included — and shows you the store, the path, and a highlighted snippet of the hit. One result per document, with a name match outranking a match buried in the text.

Where a result *opens* depends on what you were doing when you found it. With a Salon focused, the document opens in that conversation exactly as the composer's own picker would: the Librarian announces the open, and the chat sees your later saves. Otherwise it opens in standalone Document Mode, which is attached to no conversation and announces nothing to anybody, ever. A middle-click always takes the silent route, because that is what the link itself points at.

Two limits are deliberate. Vaults belonging to archived characters are never searched — an archived character is a tombstone, and surfacing her files would be a way back in. And only documents Document Mode can actually open are searched, so every result you are shown is one you can click.

## The Scene Can Change Without Leaving the Room

A chat's scenario used to be settled at creation and settled forever. The Salon sidebar's Chat drawer now carries a **Scenario** control offering the same four tiers the new-chat dialog does — project, general, group, and (with a single LLM character present) that character's own scenarios — plus a **Custom…** box for writing one on the spot. Saving rewrites the scene, recompiles every participant's identity stack so the change reaches the prompt rather than merely the record, and posts a Host announcement worded as a *revision*, so the scene-setting further up the transcript reads as superseded rather than contradicted. Saving an empty custom scenario clears the scene; re-picking the scene already in force does nothing at all, quietly. The original scene-setting message is left where it is.

The control opens on whatever is actually in force — text matching a preset preselects that preset; anything else opens on **Custom…** with the text loaded and ready to edit. The Markdown transcript export carries the change notices in the body, since a reader who saw the story relocate unremarked would be entitled to feel misled.

## The House Speaks to Its Residents Directly

### Person Consistency

The assembled system prompt has always opened by telling a character "You are —" and then, a few blocks later, started talking about her in the third person: her aliases, her pronouns, her appearance, all described to her as though she were somewhere else. The pronouns block went so far as to instruct her to use her own pronouns "when referring to this character," which is a sentence nobody should have to parse about themselves.

Every block whose subject is the speaking character is now second person. Aliases: "You also go by…" Pronouns: "Your pronouns are… Use them whenever you refer to yourself in narration." Appearance keeps its noun phrases, because that text is shared with the image pipelines, but arrives under "This is how you look —". The manifesto, the personality, and the example dialogues get wrappers that fix who is being addressed: *what you hold as true about yourself*, *what you know about yourself that others do not see unless you show them*, *how you speak*. Outward-facing renderers — the public identity card, the other-participants block, the Host's whispers — stay firmly in the third person, because their subject really is somebody else.

The final block of the prompt got the same treatment, and a live grammar bug went with it. Tool reinforcement used to read "When Ariadne uses workspace tools, *she* CALLS them," with the pronoun looked up from the character record — which meant that every character with no pronouns recorded was told "they CALLS them — they does not merely describe calling them." Second person needs no pronoun lookup at all.

Compiled identity stacks are now stamped with a builder version, and reading one requires exact equality — older, newer, and unstamped maps all read as stale and rebuild lazily on the next turn, so no migration is involved. A golden-hash table in the test suite makes forgetting the version bump impossible in either direction. The character generators were brought into line at the same time: the Wizard, Summon From Lore, and the Optimizer are each told which form of address a field takes, and the Optimizer is explicitly forbidden to flip one while rewording. Every prompt field in the app now shows a worked "Written as: …" example in its own correct person, from one shared source rather than three divergent ones.

### Standing Instructions

Projects and groups have each had an `instructions` field for some time. The project's rode along in a periodic whisper; the group's had no consumers whatsoever and went precisely nowhere. Both are now rendered into the stable, cacheable part of the system prompt as a `[STANDING INSTRUCTIONS]` section — the project's, plus the instructions of every group the *responding character* belongs to, sorted by name so the cache stays deterministic and emitting nothing at all, byte for byte, when there is nothing to say. Groups gained the missing plumbing along the way: the field is now accepted by the create and update routes that used to reject it, and the group editor has the Markdown editor the project settings card already had. The Prospero project whisper stopped carrying the instructions, since it would otherwise duplicate them every reinjection.

### Group Scenes Stop Being Committee Meetings

A multi-character scene had a tendency to become a queue: ask the room a question, and each character in turn would answer it, at length, agreeing with the last. Anti-chorus discipline addresses the failure directly, so a character with nothing to add can let the moment pass.

## Providers, Pictures, and Profiles

### NanoGPT Arrives

A new bundled plugin adds **NanoGPT**, a pay-as-you-go gateway fronting 600+ chat models, 200+ image models, and two dozen embedding models behind a single API key that covers all three. Chat is OpenAI-compatible with streaming, tool calling, JSON response formats, and reasoning routed into the Salon's thinking fold. Images pin base64 with a URL-download fallback and query the dedicated image-model listing, filtered to models that actually generate rather than edit or upscale. Embeddings discover their models live.

Three follow-ups arrived within the cycle. **Reasoning Effort** (none through xhigh) is a profile option forwarded as the gateway's own parameter, and the plugin declares its thinking-turn rule so a multi-character turn on a thinking profile anchors in prose rather than a prefill. The reasoning display was reading the wrong wire field, which is why the thinking fold stayed empty for most routed models. And the gateway has a habit, on some routed paths, of re-emitting the entire answer down the reasoning channel after the content stream ends — rendering your whole reply a second time inside a fold at the bottom of the message. The plugin now holds post-prose reasoning while it remains a verbatim prefix of the prose: diverge and it commits in full as genuine thinking; still mirroring at the end and it is the echo, and is dropped.

### Fetch Models, Honestly

The image-profile editor gained a **Fetch Models** button, and — more to the point — something for it to do. Four of the five image-capable plugins previously "implemented" model listing by handing back their hardcoded list even when given an API key; only OpenRouter ever asked. Each now genuinely queries its provider, filtered to models that actually produce images: OpenAI to the Images-API families, Google to imagen models exposing `predict` plus gemini models with image output, Grok to xAI's dedicated endpoint, Z.AI to its image-model set. Without a key you get the curated list, unchanged. On a live-fetch failure the providers now throw rather than silently substituting the static list, so the response can honestly label itself as coming from the provider or from the built-in catalogue — and the form tells you which one you are looking at. Only genuinely live lists are cached.

**Z.AI became a real image provider** in the process. The plugin had shipped one for some time, but the UI never wired it up and generation was broken end to end: Z.AI returns image URLs, and every consumer in Quilltap reads base64, so a generated image simply evaporated. The provider now downloads the URL and returns bytes.

### LoRA Adapters, and Options From the Model Itself

An image profile can now carry **LoRA adapters** — a list of `{ source, scale, trigger phrase }` rows naming small trained weights that steer a base model toward a style, a subject, or a look you cannot reach by prompting. They live in the profile's existing parameter bag: no schema change and no migration. A provider opts in by declaring the capability, per model or provider-wide, at which point the host shows the editor, caps the list at whatever that model will take, and hands the adapters over at generation time. A plugin that declares nothing never sees the key, so no other provider changed. NanoGPT is the first to take it up, mapping the one canonical list onto whichever of three wire dialects the chosen model family speaks — and a LoRA-capable model whose dialect it does not recognise gets a "family unknown" warning in the log rather than a body the model would quietly ignore.

Each row has a **Query** button beside its Source. It reads the repository's public card off HuggingFace and reports what the card actually says: the base model it names, whether the repository is tagged as an adapter, which `.safetensors` files it holds, whether it is gated, how many people have downloaded and liked it, and the trigger phrase declared in its metadata — which one further click copies into the row. Nothing else is touched, and the Source is never rewritten. The lookup runs server-side, so your browser never contacts HuggingFace and an optional access token never travels in a query string. Two facts are stated in the panel because they have consequences: a repository holding more than one `.safetensors` is ambiguous when named as bare `owner/name` and the provider picks for you, and a gated repository needs a token that only some models accept. A 401 is reported as "missing or private" rather than "does not exist", HuggingFace answering identically for a repository that is absent and one you are not allowed to see.

The panel deliberately makes no claim about whether an adapter will *work* with the selected model — that would mean matching provider model ids against HuggingFace base-model strings, and a confident "incompatible" on an adapter that works is worse than saying nothing. It shows the facts; you decide. What the help now covers instead is the failure that raises no error at all: an adapter trained for a different base model, a missing trigger phrase, or a prompt that never asked for the thing the adapter was added to supply. And, for story backgrounds specifically, the two conditions the candid draft requires — the chat must genuinely be flagged, and the adapter must sit on the profile named under Uncensored Providers rather than on whichever profile the chat happens to use — with a note on how to tell those two failures apart afterwards by reading the prompt stored on the finished image.

The image-profile editor's hand-written per-provider switch is replaced, for providers that implement the new options hook, by the same schema-driven panel the connection-profile editor uses, fetched per model and refetched when the model changes. NanoGPT's size list and image-count ceiling now come from that model's own advertised capabilities rather than from a table in Quilltap.

**And image parameters now reach every picture, not merely the ones made in chat.** Five call sites built generation parameters independently and three of them read exactly one key off the profile, so anything you configured worked for `generate_image` in the Salon and was silently dropped for avatars, story backgrounds, the images API, and the wardrobe's preview portrait. All five go through one builder now — which means those four paths honour the profile's negative prompt, seed, guidance scale and steps for the first time, and the wardrobe preview asks the provider for a portrait instead of demanding a hardcoded size only OpenAI ever accepted. Two related repairs: a NanoGPT LoRA *preset* set without an adapter beside it was being dropped before the wire, so the generation succeeded, billed, and came back with none of the requested style; and a failed image request now logs the model, size, dialect and the request's key names at `error` rather than `debug`, since NanoGPT returns the same generic 400 for a bad adapter source, an unreachable repository, an unsupported size and a filtered prompt, and packaged instances keep no debug log to tell them apart.

### Characters Can Look at Photographs

Five defects, all downstream of a single image a user shared that no character could see.

The worst of them was silent. A profile's "Supports image attachments" checkbox says the *model* can read pictures; it says nothing about whether the *plugin* can send them — and four plugins stripped every attachment before the wire. So ticking that box on a genuine vision model switched off the description fallback *and* handed the bytes to something that threw them away, and the model wrote a confident paragraph about an image it had never received. Both questions are now asked, through one predicate that reads the plugin registry: where the model can see but the plugin cannot send, the request routes to a description instead of losing the picture. The same check guards describer selection, which had been willing to appoint a describer that could not receive the image either.

Characters also gained `describe_image`. They had three image tools and all three were custodial — file this picture, show this picture to the room, list the catalogue — and not one of them answered "what is in this photograph?", so models reached for the show-it tool and were told to file the image first. `describe_image` serves the description written at upload, or the prompt that generated a Quilltap-made image, or a fresh vision call, and does not require the image to be in the caller's album.

The same shape turned up a third time before the cycle closed, in the Z.AI plugin, which kept a private list of which GLM models read pictures and matched only ids carrying a `v` after the generation number. Z.AI's 5.3 line reads images without one, so `glm-5.3-flash` had every attachment stripped at the plugin with "does not support image input" — while the profile's own checkbox had asserted the opposite and switched off the description fallback. The list is deleted rather than extended: whether a model can see is the host's question, answered by the profile; whether the transport can carry the bytes is the plugin's, answered by the MIME check. A regex pinned to last year's naming convention is stale the day the vendor drops a suffix.

A fourth instance closed the family. With the Concierge in Auto-Route mode, a refused turn is retried and then rerouted to the uncensored profile — carrying the message array built for the *original* profile, with the attachment question already answered for it. On a turn carrying an image, a vision-capable primary had correctly embedded the raw bytes and the text-only substitute received them: a 400, an empty response, and a character who said nothing at all, with both sides of the configuration perfectly correct. The reroute now re-asks the attachment question against the profile it is actually about to call, so an image a stand-in cannot read becomes its description exactly as it would have if that profile had been the primary; and the search for an uncensored route is *ordered* by what can carry the payload rather than filtered by it, because a described image beats no reroute at all. The wider lesson was that "can this profile receive this attachment?" had three independent spellings in the codebase — which is precisely the drift that produced this bug and the three before it. There is one now, and all three sites call it.

And every full-size image viewer in the app now has a **Download** button. Several had none — a real problem in the desktop shell, where right-click → Save Image is not available — and two more hand-rolled the anchor-click trick and so missed the native save dialog. All of them now go through the same Electron-aware helper.

### Connection Profiles Send What They Say

A run of repairs this cycle came down to profiles whose settings were being recorded and then not used. **Max Tokens** and **Top P** were saved and never sent. **Max Context** was saved and ignored by the context budget, which used its own idea of the window. Ollama profiles could not set a request timeout and did not drive the server's context window. Local and OpenAI-compatible providers did not send the profile's parameters at all, and OpenAI-compatible endpoints could not call tools. An API key would follow a profile when you pointed it at a different provider, and so would a base URL onto a provider that does not show one. Clearing a numeric option left the old value in place. Profiles can now be tagged. The multi-character `[Name]` prefill became a per-profile setting rather than a global one — and, since a thinking model rejects or silently swallows a prefilled assistant turn, a migration turns it off on the profiles that run one.

### Every Profile Can Name an Understudy

When a call through a connection profile failed outright — a rejected key, a rate limit, a network error, a model that is no longer there, a 5xx, an empty response, a moderation refusal — the call failed, and that was the end of the turn. A profile can now name an **understudy** to try instead, and may optionally permit one further stand-in of the same or better model class, auto-picked. Each call is capped at three attempts: your profile, your understudy, one tier pick. Chains do not recurse, so an A→B, B→A arrangement is legal configuration that simply stops rather than spinning. And there is no stickiness — a successful fallback applies to that call and no other, so the next message tries your primary again, as it should.

The tier pick is off by default, on the principle that spending money at a provider you did not choose is not a thing to do quietly. When it is on it excludes Courier profiles, anything with no usable key, and anything below the tier that just failed; it insists on a danger-compatible profile in a dangerous-routed context; and it prefers a different provider over a higher-tier sibling of the one that just let you down.

The one preference the chain overrides is modality. A chain swaps the model but reuses the message array built for the primary, so on a turn carrying an image the raw bytes are already in it — handing that to a text-only stand-in is a guaranteed 400, which is exactly the shape of the reroute bug above. Both steps therefore require vision when the turn carries images, the *named* understudy included. Every other choice you made is honoured as you made it; this one is an incompatibility rather than a preference.

It is wired in at four places. The Salon's hard errors walk the chain and say so as they go, emitting a "failing over" stage per attempt — but only before the first word of prose has reached you: once a character has started speaking, a partial answer is preserved rather than substituted. Empty responses try the chain third, after the same-profile retry and the uncensored reroute, both of which answer their own cases better. Cheap-LLM tasks re-issue against each stand-in with a fresh deadline, governed for provider-picked selections by a new **Allow a Similar-Tier Stand-In** switch in Cheap LLM settings. And image description runs the describer's chain before falling through to the uncensored describer. When a chain is exhausted, the error names every profile that was asked and how each one declined.

Both new fields ride through export, import, backup and restore, with the understudy's id remapped on each path — without which every restored chain would point at a profile the new account has never heard of. Deleting a profile clears it from every profile that named it.

## The Concierge Learns Who Decided

The per-chat Concierge switch had three states doing the work of four. Underneath it are two independent questions — *who decided this chat is spicy*, the classifier or you, and *where does it route*, ordinary providers or uncensored ones — and one corner of that square was unreachable. Vouching a chat off-duty dropped the uncensored profile ids entirely, so an operator who knew perfectly well what they were writing got concealed prompts on the default image profile, and the only route to the uncensored providers ran through convincing the classifier.

There are four states now, grouped in the dropdown by who is doing the deciding. Under **The Concierge decides**: **Monitored** (formerly "Safe" — the classifier keeps watch and may flip the chat to Flagged on its own) and **Flagged** (unchanged — the classifier's verdict, uncensored routing, danger styling). Under **You decide**: **Vouched Safe** (formerly "Off-duty" — you vouch for the chat, no classification, no scanning, ordinary providers) and **Uncensored**, which is new. Uncensored takes every route Flagged takes — uncensored text and image profiles, candid story-background drafts, uncensored cheap-model tasks — with no classification, no scans, no announcements, and no danger styling, and it works even when the global Concierge mode is off. It is the state for a chat whose nature you already know and would rather not have adjudicated.

The Salon header pill renders per state (red for Flagged, grey for Vouched Safe, blue for Uncensored, nothing at all for Monitored), and every manual transition posts its own announcement. Under the hood an overloaded predicate that had been answering all three questions at once was deleted and its twenty-odd call sites split between three that each answer one — *should this route uncensored*, *should this wear danger styling*, *is the classifier on duty* — and the two classifier gates that used to read the raw column now go through the helper, so the new state cannot be reclassified out from under you. **Existing chats keep their exact behaviour**; the migration only records that the column's domain has widened.

## The Commonplace Book Keeps Up

A character's vault holds a summary of every conversation it has taken part in, and the Commonplace Book searches that shelf to build the "Relevant Past Conversations" a character is shown. That list used to refresh on three cadences only — the opening recap, each summary fold, and turns that reach explicitly for the past — so between folds it stood still while the conversation wandered several turns away from the dialogues the character was still being pointed at.

A new instance-wide setting, **Consult past conversations every turn** (Settings → Memory → Recall Relevance, off by default), re-runs that search every turn. The reason it can afford to is that it costs no extra embedding call: the turn's memory search already embedded a vector for exactly this sentence, and the conversation-summary search now reuses it rather than paying to embed the same words twice. Where no vector is available — memories skipped, no embedding profile, a failed call — the cadence sits the turn out rather than spending anything of its own. The per-turn list is deduplicated against the standing fold whisper and the retrospective recap alike, so no conversation is ever listed twice to the same character in one turn, and the list length ramps with the profile's context window.

**Help search learned to read sections.** Help documents were embedded one vector per file, which for a 700-line page spanning a dozen subsystems is a smear that matches no specific question strongly — and the tool then handed the model the first thousand characters of the file, which is a table of contents rather than an answer. A new chunk table holds section-level slices, rebuilt whenever a document's content hash changes and embedded with the document title and nearest heading prefixed, so a section carries the context of the page around it. The Guide's own search box, which had only ever matched titles, now searches document text server-side and shows a snippet centred on the hit.

## Under the Floorboards

### The Managed Virtual Machines Are Gone

Quilltap used to offer to build you a Linux virtual machine and run itself inside it — Lima on macOS, WSL2 on Windows — so that the desktop shell could put a real kernel boundary between the assistant and your files. That arrangement is withdrawn. `quilltap-shell` 4.2.0 removed both modes from its side; 4.9 is the server half. **The strongest isolation Quilltap ships is now Docker**, and a virtual machine of your own making, with or without Docker inside it, is as supported as it ever was — the building of it is your affair.

Gone from the build: the `lima/` directory and its init script, the rootfs builder, the `wsl2` stage in the CI image, and the four rootfs steps in the release workflow. Releases no longer attach `quilltap-linux-amd64.tar.gz` or `quilltap-linux-arm64.tar.gz`. The Docker images — amd64, arm64, and the multi-arch manifest — and the standalone tarball that the `quilltap` CLI and the Electron shell actually download are unchanged.

Gone from the app: the Lima branch in platform detection, the `lima` and `wsl2` environment types on the instance lock, the `vm` and `electron-vm` runtime modes a character sees in its own self-inventory, the Almanack's `lima` runtime type, the `VM` and `Electron+VM` badges in the footer, and the `isVM` field the data-directory endpoint used to report.

The part worth reading closely is **host URL rewriting** — the trick that lets a containerised Quilltap reach a model server running on your desktop. It had five strategies for finding the gateway; three existed for Lima, and two of those were actively wrong under Docker, returning a bridge address that reaches nothing on the host's loopback. There are two now: `QUILLTAP_HOST_IP` if you set it, then `host.docker.internal` inside Docker. In a self-managed VM, `QUILLTAP_HOST_IP` is the supported route — it both switches rewriting on and supplies the address. `@quilltap/plugin-utils` 2.6.0 carries the same change, and `qtap-plugin-mcp` 1.1.37 takes it up; that plugin bundles the rewrite itself because MCP servers validate the `Host` header and need a custom fetch rather than a rewritten URL.

`docs/WINDOWS.md`, which was a WSL2 troubleshooting guide and nothing else, is deleted. The README and the About page now describe the shell's three back ends — **Direct** (the Node server inside Electron), **Docker**, and **Remote** (any Quilltap URL, including a dev server or an `npx quilltap` instance) — in place of the old VM/Docker toggle.

### A Lost Key Can Be Cut Again

The `.dbkey` file is only a wrapper; the pepper inside it is the actual database key. Anyone holding the pepper could therefore always rebuild the wrapper — but the only way to do it ran through the server's own unlock endpoint, which wants a running server. That covers a lost key file and nothing else. A *forgotten passphrase* left you at the locked screen, being asked for the one thing you no longer had, with no offline way in.

`npx quilltap instances restore-key <name>` writes the key file with the server down. The pepper comes from `ENCRYPTION_MASTER_PEPPER` or a hidden prompt, never from a flag, because a command line lands in shell history and in `ps`. Before writing anything it opens every encrypted database in the instance with the candidate pepper and refuses if one fails — a `.dbkey` holding the *wrong* pepper is worse than none at all, since the server unwraps it happily, hands the database a key that decrypts nothing, and reports intact data as corrupt. That proof cannot be waived while there is an encrypted database to check; `--force` covers only a fresh or still-plaintext instance. The command is lock-gated, an existing key file is backed up beside itself, and the minimum-server-version stamp the Electron shell reads is carried across the rebuild.

It does not re-encrypt character archive bundles, which are sealed with the passphrase rather than the pepper — only the server's Change Passphrase card rewrites those — and it says so when the passphrase changes.

### The Cheap Model's Budget Was Its Own Ceiling

The small background tasks — titles, summaries, memory extraction, scene tracking, compression — run against a cheap model on a deadline. Those deadlines were round numbers chosen by eye, and once the log started naming a failed cheap task it became possible to see what they had been doing. Across 1,971 completed non-compression calls on a live instance, **not one had ever taken longer than the budget**, and three task types peaked within six hundred milliseconds of the wall. That is not a distribution; it is a censored one. The maxima were the ceiling, not the work. Compression showed the same shape against its own higher limit. In the first sixty hours after the failure log existed, eighty-one passes were lost, every one of them to a timeout.

Four changes followed. The shared remote budget goes from 45 seconds to 90 and compression's from 75 to 120 — set well clear of the old wall rather than just past it, since the true tail is unknown *because* it was censored, and the point is to stop cutting the curve so the histogram can be read at all. The ceiling now follows **who is waiting** rather than only which task it is: work done in the background gets the generous number, while anything awaited inline while a turn assembles keeps the short one, because those tasks produce optional context and losing one costs a character some remembered flavour rather than the turn. A timed-out attempt gets one more go on a fresh socket — only a timeout, since a rejected key or a refusal would fail identically the second time.

And, most consequentially, **a cheap task lost to a timeout no longer looks like one that finished.** Six job handlers now fail rather than return: scene-state tracking, title update, context summary, story background, and both memory extractors. Before this, every job in the measured window came back COMPLETED — 83 memory extractions, 99 scene-state passes, zero failures — over 45 passes that never happened. A failed job now takes the existing backed-off retry and then goes dead with its reason attached, which is a third attempt at the work and the first time the loss is visible to anybody. One consequence is worth knowing: a memory extraction that throws discards the whole turn's buffered writes, so the retry re-runs atomically with no duplicates, but the passes that *did* succeed go with it. That is the right trade when the retry works, and worse data with better information when it does not — and a provider timing out three times against a 90-second ceiling is a configuration you want to be shown rather than have absorbed.

## Repairs

Forty-six defects were catalogued and fixed across the cycle, most of them found by walking the application as a user rather than as its author. A representative handful: chat titles and story backgrounds silently stopped working because a cheap model misspelled a single key; the standalone tarball was smuggling the build host's native modules into every target; the tool-result error sentence the emitter carefully composed never reached the interface, so a failed image generation said nothing about why; DeepSeek's thinking models returned a 400 on every character turn because prefill-hostility was scoped to providers rather than to thinking models; hover states across the entire application resolved to no CSS rule at all and therefore did nothing; a character's photo gallery had no reachable way to download a picture, the controls being painted over by the page toolbar; creating a project with a blank description failed with a silent 400; and shell completion stopped working the moment a flag appeared on the line.

Three more arrived late and are worth naming. A `.qtap` bundle carrying a single malformed connection profile used to import *nothing at all* — the new legacy-field seeding sat outside the loop's per-item guard, so one hand-edited record threw past everything else in the file; the helper is now total over junk input and the call has moved inside the guard, where a bad item is named in a warning and the rest of the bundle lands. Deleting memories in bulk — a full-wipe restore, or a large character cascade on an instance with tens of thousands of them — failed outright on SQLite's variable limit rather than deleting; the queries chunk now, and the last remaining per-row bypass of the deletion chokepoint was routed back through it. And a cheap task that dies now says in the server log which task it was, on which provider and model, in which chat — where it previously arrived as an anonymous provider error, and where reading those lines led directly to the budget work above.

The document tools accounted for two more, both of them cases of a tool blaming the file for a fault of its own. An edit arriving without its `find` argument was answered with "Text not found in file" — advice that cannot possibly help, since the fault was in the call — so the character dutifully re-read the file and made the same malformed call again; the handlers now check their arguments before opening anything and name the one that is missing. And an edit could be refused over punctuation: models write curly quotes and em dashes when they write prose, Quilltap stores what they write, and a later turn retyping that sentence with a straight apostrophe — which models routinely do — found nothing to match. Re-reading did not help, because the retyping came out the same way; five valid edits were refused this way on one instance. Exact matching still wins wherever it finds something, but where it finds nothing at all the tools now fold typographic variants together, write the replacement in the spelling the caller used, and say that the fold was needed, so the model learns the file's punctuation differs from its own. Quilltap's own typography was not involved and did not change: nothing curls a quote on its way to a tool, an export, or a model.

Sliders, finally, look like part of the application. All fifteen `<input type="range">` controls in the app had been carrying five different ad-hoc idioms between them: six set no accent at all and rendered in the browser's default system blue whatever theme you were running, two discarded the filled portion of the track and showed a flat grey bar that said nothing about its own value, and two more wore a *text-field* style, complete with input border. There is one token-driven class now, and sliders have a themed focus ring for the first time.

The hover-state failure earned a permanent guard. A `qt-*` class that resolves to nothing is indistinguishable, at every automated layer available, from one that resolves and happens to inherit — the markup renders, TypeScript is satisfied, the linter has no opinion, and the test renderer does no cascade. Only a person looking at a real browser can tell. `npm run lint` now fails the build on an undefined `qt-*` utility, and on any `qt-*` token carrying a variant prefix, which is the shape that let most of that family go missing in the first place.

## Upgrading

**Five migrations run on first boot.** `create-help-doc-chunks-table-v1` adds the section-level help chunks described above, and — because an already-upgraded instance has every content hash matching and would otherwise skip every file forever — a backfill slices any already-synced document when the chunk table is empty and enqueues the jobs that fill in the vectors. Measured on a real instance: 588 chunks across 120 documents, embedded inside a minute. `add-profile-multi-character-prefill-field-v1` moves the multi-character `[Name]` prefill from a global switch to a per-profile one, and `retire-prefill-on-thinking-profiles-v1` then turns it off on profiles that run a thinking turn, since those reject or silently swallow a prefilled assistant turn. `add-profile-fallback-fields-v1` adds the two columns an understudy needs, both defaulting to nothing, and a fifth records only that the per-chat Concierge column now admits a fourth value. All of them are safe to run more than once.

**Your chats will be re-dated once, on the first boot.** The new "last time somebody spoke" timestamp is calculated for every existing chat as a startup step, which the loading screen names while it runs. Nothing else about a chat is touched — but expect the lists to re-order, sometimes considerably, since a conversation whose date was being held aloft by a story background or a Staff announcement will drop to where it actually belongs.

**Nothing is required of you for fallback chains, LoRA, or the Concierge's fourth state.** No profile has an understudy until you name one, and the auto-picked tier stand-in is off until you switch it on. LoRA adapters live in a profile's existing parameter bag — no schema change, no migration, and no adapter until you add one. Every existing chat keeps the exact Concierge behaviour it had; the two renamed states, Monitored and Vouched Safe, are the same states wearing clearer names.

**Provider prompt caches roll cold exactly once.** The system prompt gained the standing-instructions section, which is a structural change, so the cache structure version moved from 3 to 4. Nothing needs doing; the first turn on each character after the upgrade is merely a little dearer than the second. Compiled identity stacks likewise rebuild lazily on first use — a stamped envelope, no migration, no visible pause.

**Realtime needs its upgrade requests passed through.** If you run Quilltap behind a reverse proxy, forward the `Upgrade` and `Connection` headers so the WebSocket can establish; the socket is same-origin only, so the proxy must also present the instance under the origin the browser is using. Where it cannot connect, every surface falls back to the polling it did in 4.8 — you lose the immediacy, not the function. The tasks queue's "Auto-refresh (5s)" switch is now labelled "Fallback polling (5s)": same switch, honest name.

**NanoGPT needs a key of its own.** It is a new API key type; a NanoGPT connection, image, or embedding profile expects a `NANOGPT` credential rather than borrowing an OpenAI-compatible one.

**Nothing is required of you for the wardrobe or scenario changes.** Archiving is opt-in and adds no state to anything you have not archived; `Wardrobe/instructions.md` is read where it exists and skipped where it does not. Existing chats are untouched by the mid-chat scenario control — a chat's scene changes only when you change it.

**If you were running the Lima or WSL2 back end, you must move.** Update the desktop shell to 4.2.0 or later and choose another mode: **Docker** if you want the assistant kept behind a door — it is the strongest boundary Quilltap ships, and the recommended arrangement; **Direct** if you would rather the Node server simply ran inside Electron; **Remote** if you keep Quilltap elsewhere and want the window pointed at it. Your instance data is untouched by any of this — the data directory is the same on either side of the change. If you run Quilltap inside a virtual machine you built yourself, nothing is taken from you, but set `QUILLTAP_HOST_IP` to your host's address: it is now both the switch that enables host URL rewriting and the source of the address, the `/proc/net/route` and `/etc/hosts` guesses having gone with Lima. And if you were pulling `quilltap-linux-amd64.tar.gz` or its arm64 twin from the releases page, those were the VM rootfs images and are no longer built; the standalone tarball and the Docker images are unchanged.

Node.js 24+ is still required, unchanged from 4.8.

## Installation

### Electron Desktop App

Download the latest `.dmg` (macOS), `.exe` (Windows), or `.AppImage` (Linux) from the [quilltap-shell releases page](https://github.com/foundry-9/quilltap-shell/releases/latest). The window is only ever a front end, and it offers three back ends: **Direct** (the Node server inside Electron, no isolation), **Docker** (the container image behind a native window — the recommended arrangement, and the strongest boundary we ship), and **Remote** (any Quilltap URL, including a dev server, an `npx quilltap` instance, or a machine on your network). Requires shell 4.2.0 or later.

### npm (Node 24 required)

```bash
npm install -g quilltap
quilltap
```

Open `http://localhost:3000` in your browser. Requires Node.js 24+. First run downloads and caches locally.

### Docker

```bash
docker pull foundry9/quilltap:4.9.0
```

Or use the startup scripts:

```bash
# Linux / macOS
curl -fsSL https://raw.githubusercontent.com/foundry-9/quilltap-server/refs/heads/main/scripts/start-quilltap.sh | bash

# Windows (PowerShell)
irm https://raw.githubusercontent.com/foundry-9/quilltap-server/refs/heads/main/scripts/start-quilltap.ps1 | iex
```

### Standalone Tarball

Available for environments where npm global installs and Docker are both impractical, and unchanged by this release. Note that the two `quilltap-linux-*.tar.gz` archives are no longer published — those were the Lima and WSL2 rootfs images, not this. See the GitHub releases page for download links.
